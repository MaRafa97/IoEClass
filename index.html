Aprenderemos los tipos de conexión, configuración básica de microcontroladores (como el ESP32), fundamentos de programación de sensores y los protocolos necesarios para transmitir datos a la nube de manera segura.

Redes para IdT

Tipos de Conexión Inalámbrica

WiFi

El más común en dispositivos domésticos (cámaras, smart TVs). Ofrece un gran ancho de banda pero consume mucha energía, por lo que no es ideal para baterías pequeñas.

Bluetooth (BLE)

Bluetooth Low Energy. Excelente para dispositivos que dependen de baterías a corta distancia, como smartbands y sensores médicos portátiles.

Zigbee

Estándar ampliamente usado en domótica (focos, asistentes). Permite formar redes en malla (mesh) de muy bajo consumo energético.

LoRaWAN

Transmisión de baja velocidad, pero ideal para sensores en zonas rurales o industriales que deben enviar datos a varios kilómetros de distancia.

Primeros Pasos y Amenazas

Configuración Inicial y Riesgos

¿Qué implica configurar un objeto?

Al implementar una solución IoT con hardware como ESP32 o Raspberry Pi, la configuración básica requiere:

  • Asignar credenciales de red (SSID/Password).
  • Configurar su dirección (IP estática o dinámica).
  • Definir cómo y a qué servidor (ej. API en la nube) enviará los datos.

El Peligro del "admin/admin"

El primer gran problema de seguridad de IoT. Muchos dispositivos salen de fábrica con usuarios por defecto. Si no se cambian, el dispositivo queda totalmente vulnerable desde Internet.

Caso Histórico: Botnet Mirai (2016)

Este malware buscó dispositivos conectados con credenciales por defecto, los infectó y convirtió miles de cámaras IP en una red zombie para lanzar ataques de Denegación de Servicio (DDoS).

Lógica y Lenguajes

Fundamentos de Programación IoT

El Bucle del Script (Loop)

Un programa IoT no suele ser muy complejo en estructura, pero sí crítico. Consiste en automatizar estos tres pasos:

1

Leer Datos

Capturar valores del mundo físico (ej. Sensor DHT22 de humedad).

2

Procesar

Usar condicionales en el código. Ej: if (temp > 30) { alerta(); }

3

Enviar / Actuar

Mandar la métrica a un dashboard en la nube o accionar un elemento físico.

Lenguajes de Programación

C / C++ (Arduino IDE)

El más popular para hardware (Arduino, ESP32). Es simple pero permite un control directo de pines mediante librerías.

Python (MicroPython)

Lenguaje muy versátil usado en placas como Raspberry Pi Pico. Ideal para prototipado rápido e integraciones en la nube.

JavaScript (Node.js)

Utilizado masivamente para construir paneles de control, servidores y herramientas lógicas visuales como Node-RED.

Protocolos y Cifrado

Cómo hablan las máquinas

MQTT

El estándar ligero de IoT. Usa un modelo de Publicar/Suscribir a través de un Broker central. Es ideal para enviar datos desde sensores con escasos recursos.

HTTP / HTTPS

El protocolo web tradicional. Ocupa más ancho de banda pero es útil para plataformas API (ej. ThingSpeak) para grabar datos directamente con peticiones GET/POST.

CoAP

Constrained Application Protocol. Diseñado para IoT de extremadamente bajo consumo; emplea UDP en lugar de TCP para minimizar la carga de red.

Seguridad Básica en Tránsito

Transmitir datos por HTTP envía la información en texto plano. Cualquiera que intercepte la red wifi (Sniffing) puede leer métricas o contraseñas. Para garantizar confidencialidad, las transmisiones IoT siempre deben ir cifradas usando capas como TLS/SSL (empleando HTTPS o MQTTS).

Bases Conceptuales

El Paradigma de la Convergencia TI/TO

Tecnología Operativa (TO)

  • Determinismo Estricto

    Los sistemas físicos requieren tiempos de respuesta garantizados y predecibles (latencia en milisegundos). Un retraso en una válvula puede causar fallos catastróficos.

  • Hardware Específico

    Uso intensivo de Controladores Lógico Programables (PLCs), Unidades Terminales Remotas (RTUs) y sistemas SCADA con ciclos de vida de 15 a 20 años.

  • Seguridad Física Prioritaria

    La prioridad no es la confidencialidad de los datos, sino la disponibilidad del sistema y la seguridad humana (Safety).

Tecnologías de Información (TI)

  • Procesamiento Asíncrono

    Gestión masiva de datos y transacciones (ERP, CRM) donde la latencia variable y ocasional son tolerables sin riesgo de destrucción física.

  • Estandarización y Escalabilidad

    Infraestructura basada en hardware genérico (servidores, virtualización), redes IP estándar e iteraciones rápidas (ciclos de vida de 3-5 años).

  • Tríada CIA

    El objetivo principal es la Confidencialidad, Integridad y Disponibilidad de la información corporativa frente a accesos no autorizados.

Jerarquía de Arquitectura Estándar

El Modelo Purdue (ISA-95)

El Modelo Purdue es el estándar de la industria para segmentar arquitecturas empresariales y de control en zonas lógicas para garantizar funcionalidad y seguridad.

Nivel 4 / 5: Red Corporativa y Empresarial

Sistemas ERP, gestión logística, correo e Internet. Dominio puro de TI.

ZONA DESMILITARIZADA (DMZ)

Nivel 3: Operaciones del Sitio / Fabricación

Sistemas de Ejecución de Manufactura (MES). Coordina la producción.

Nivel 2: Control de Supervisión (SCADA)

Sistemas HMI y servidores SCADA que supervisan áreas de la planta.

Nivel 1: Control Básico

Controladores lógicos programables (PLCs). Ejecutan la lógica determinista.

Nivel 0: Proceso Físico

Sensores, actuadores y robótica. El mundo físico real.

Estrategias Computacionales

Modelos de Procesamiento en IdT

Edge Computing

Definición: Procesamiento de datos en el perímetro de la red, físicamente cerca de los sensores/actuadores (Niveles 1-2).

Beneficios:

  • Latencia ultrabaja (respuestas en milisegundos).
  • Reducción drástica del ancho de banda hacia la nube.
  • Mantenimiento de privacidad de datos sensibles localmente.
  • Toma de decisiones crítica ininterrumpida sin internet.

Cloud Computing

Definición: Uso de infraestructuras centralizadas escalables para procesamiento pesado y almacenamiento a largo plazo.

Aplicaciones IdT:

  • Entrenamiento de algoritmos pesados de Machine Learning.
  • Análisis histórico de macrodatos de múltiples plantas.
  • Despliegue de Gemelos Digitales complejos.
  • Visualización y dashboards ejecutivos (Nivel 4/5).

Elementos Físicos y Lógicos

Impulsores de la Transición Tecnológica

Sensores Inteligentes

Evolucionan de señales simples a dispositivos con autodiagnóstico. Protocolos como IO-Link permiten transmitir no solo la lectura, sino temperatura interna y desgaste.

Pasarelas (Gateways)

El puente crucial entre lo heredado y moderno. Actúan como traductores: leen datos de un PLC usando Modbus RTU y los encapsulan en protocolos como MQTT.

Analítica Avanzada

Utilizando algoritmos de IA en el Edge o Cloud, se transforma la telemetría en insights accionables, impulsando el Mantenimiento Predictivo.

Superficie de Ataque

Conectar redes previamente aisladas (Air-Gapped) a TI crea nuevas puertas de entrada para actores maliciosos.

Amenazas en Entornos TO

Vulnerabilidades Estructurales

1. Protocolos Inseguros

Protocolos como Modbus y DNP3 asumen redes de confianza física. Carecen de autenticación o cifrado nativo, permitiendo inyección de comandos.

2. Fin del "Air-Gap"

La convergencia IdT elimina la barrera física (Brecha de Aire), abriendo el camino para la propagación lateral de malware desde redes corporativas.

3. Impacto Ciberfísico

A diferencia de TI donde se pierden datos, un ataque en TO altera los procesos físicos, resultando en riesgo real para vidas humanas o destrucción material.
